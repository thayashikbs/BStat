7 ロジット/プロビット回帰分析

第4回の授業では, ロジット回帰の考え方 (2値データに対する回帰, ロジスティック変換, オッズ比) を学び, R演習スクリプト R_logit_dist.R を使って, glm() による分析を行った. 本章は, この R 演習スクリプトに対応する. 使用するデータは, いずれも授業用に作成した仮想データである.

7.1 ロジット回帰分析の基本操作

ロジットモデル: シミュレーションデータ

基本操作を確認するため, ロジット回帰モデルが想定するデータ生成メカニズムに従って, 人工データを生成する. その後, このデータを使って, ロジット回帰分析を行う関数glm()を実行し, 真の係数の値が推定できることを確認する.

シミュレーションデータの生成

set.seed(1)
n <- 100
p <- 2
a <- 1.2
b <- c(0.5, 1.5)  # 真の切片と係数
X <- matrix(runif(n * p, -5, 5), ncol = p)  # 予測変数 (X1, X2)
colnames(X) <- paste0("X", 1:p)
eta <- a + X %*% b  # 線形予測子
prob <- exp(eta)/(1 + exp(eta))  # ロジスティック変換 → 発生確率
y <- rbinom(n, 1, prob)  # 0/1 の発生 (ランダム)

plot(X[, 1], y)

plot(X[, 2], y)

ロジット回帰分析の実行

ロジット回帰分析は, R関数glm()を用いて実行することができる. glm()は標準パッケージstatsに含まれているため, あらたなインストール作業は不要である.

glm()を用いた分析の操作手順や出力結果の読み方は, おおむねlm()を踏襲すれば良い.

glm()に与えるモデル式 (引数formula) の書き方は lm()と同様である. それに加えて, glm()では, 引数familyによって, 目的変数が従うと想定する確率分布を指定する. ロジット回帰/プロビット回帰では, binomial (二項分布) を指定する.

また, lm()と同様に, glm()の出力結果に対して summary()関数を適用することで, 推定結果が出力される.

# ロジット回帰
res_glm <- glm(y ~ X, family = binomial)
summary(res_glm)  # 推定値を真の値 (1.2, 0.5, 1.5) と比べよ
#> 
#> Call:
#> glm(formula = y ~ X, family = binomial)
#> 
#> Coefficients:
#>             Estimate Std. Error z value Pr(>|z|)    
#> (Intercept)   2.5815     0.8647   2.985 0.002831 ** 
#> XX1           1.1494     0.3434   3.347 0.000818 ***
#> XX2           2.7630     0.7509   3.680 0.000233 ***
#> ---
#> Signif. codes:  0 '***' 0.001 '**' 0.01 '*' 0.05 '.' 0.1 ' ' 1
#> 
#> (Dispersion parameter for binomial family taken to be 1)
#> 
#>     Null deviance: 133.750  on 99  degrees of freedom
#> Residual deviance:  34.478  on 97  degrees of freedom
#> AIC: 40.478
#> 
#> Number of Fisher Scoring iterations: 8

summary()の出力結果のlm()との主な違いは, 個別の回帰係数の有意性を見る指標が, lm()では\(t\)値であったところが glm()では\(z\)値になっている点 (それに伴い, 付随する\(p\)値の表記も変化), および, 全体の当てはまりの指標について, lm()のように\(R^2\), 補正\(R^2\)の値が表示されておらず, その代わりに, “Null deviance” (切片のみのモデルの逸脱度), “Residual deviance” (残差逸脱度) が表示されている点である.

(内挿) 予測

glm()の出力結果を関数predict()に与えることで, 内挿予測 (適合値の算出) を行うことができる. 注意点として, 引数typeを指定しない場合 (デフォルト設定) には, “線形予測子”\(\eta=\beta_0 + \beta_1 x_1 + \cdots + \beta_k x_k\)の予測値が出力される. ロジット回帰では, これは対数オッズである.

関数predict():
- 予測値を返す関数
- 引数typeの選択肢: "link"(デフォルト), "response", "terms"
  - "link": 線形予測子のスケールにおける予測
  - "response": 目的変数のスケールにおける予測 (ロジット回帰では確率)
  - "terms": 線形予測子のスケールにおける, モデル式の各項の適合値を格納した行列を返す

ロジット回帰において, 確率の予測を得たい場合には, type = "response"と指定する必要がある.

# 予測 (内挿)
eta_hat <- predict(res_glm)  # 対数オッズ (線形予測子)
p_hat <- predict(res_glm, type = "response")  # 確率
head(data.frame(y, p_hat))
#>   y     p_hat
#> 1 1 0.9846543
#> 2 0 0.0500027
#> 3 0 0.0507452
#> 4 1 1.0000000
#> 5 1 0.9448650
#> 6 0 0.3178520
plot(eta_hat, p_hat)  # ロジスティック曲線

以下のように, 線形予測子の予測値に対して, ロジスティック変換 (リンク関数\(g(\cdot)\)の逆関数) を適用すると, 確率の予測値p_hatと一致することが確認される.

# 確認: 線形予測子をロジスティック変換すると p_hat に一致する
head(exp(eta_hat)/(1 + exp(eta_hat)))
#>         1         2         3         4         5         6 
#> 0.9846543 0.0500027 0.0507452 1.0000000 0.9448650 0.3178520

係数の信頼区間

回帰係数の信頼区間は, lm()の場合と同様に, 関数confint()を使えば良い.

# 信頼区間
confint(res_glm)  # 95%信頼区間 (デフォルト)
#>                 2.5 %   97.5 %
#> (Intercept) 1.1914472 4.659417
#> XX1         0.5901329 1.974012
#> XX2         1.5989191 4.620681
confint(res_glm, level = 0.9)  # 90%信頼区間
#>                   5 %     95 %
#> (Intercept) 1.3787136 4.269921
#> XX1         0.6664132 1.818782
#> XX2         1.7488603 4.265779

7.2 データ分析例

データ1: 企業パフォーマンス・データ (集計データ, 仮想)

企業を, 規模・人材投資・SDGs活動の水準 (それぞれ高い H / 低い L) の組合せで8グループに分け, グループごとに対象企業数と, そのうち業績が優良と判定された企業数を集計したデータである.

- firmperf.txt, 8行 (規模 × 人材投資 × SDGs活動 の組合せごとの集計)
  - size: 企業規模 (H/L)
  - hr_invest: 人材投資 (H/L)
  - sdg: SDGs活動 (H/L)
  - n_tot: 対象企業数 (社)
  - n_pos: 優良企業数 (社)

データ読み込み

ファイルの先頭2行はコメントなので, 引数skip = 2で読み飛ばす. 列名は日本語なので, 扱いやすいよう英語の列名に付け替える.

perf_dat1 <- read.csv("class/firmperf.txt", skip = 2)
colnames(perf_dat1) <- c("size", "hr_invest", "sdg", "n_tot", "n_pos")
perf_dat1
#>   size hr_invest sdg n_tot n_pos
#> 1    H         L   L    60     7
#> 2    H         H   L     8     2
#> 3    H         L   H   186    36
#> 4    L         H   L     3     0
#> 5    L         L   H    86    14
#> 6    H         H   H    50    16
#> 7    L         H   H    22     9
#> 8    L         L   L    18     2

質的変数は, 関数factor()で因子型に変換し, 基準水準 (ベースライン) を引数levelsの先頭で明示的に指定しておく. ここでは, いずれも「低い (L)」を基準とする.

perf_dat1$size <- factor(perf_dat1$size, levels = c("L", "H"))
perf_dat1$hr_invest <- factor(perf_dat1$hr_invest, levels = c("L", "H"))
perf_dat1$sdg <- factor(perf_dat1$sdg, levels = c("L", "H"))

(注) 文字型のままでもglm()は実行できるが, その場合はアルファベット順に先頭の水準 (ここでは H) が基準となり, 係数はsizeL, hr_investL, sdgLのように「L であること」の効果として, 符号が逆向きに推定される. 授業のR演習スクリプトではこちらの形で出力されているので, 見比べてみると良い.

ロジット回帰の実行

ロジット回帰の実行の際, 目的変数として, glm()へは異なるデータ形式を与えることができる.

まず, 目的変数のデータ形式として, “成功 (ここでは優良) 回数”, “失敗 (優良でない) 回数” の2列を持つ行列を, モデル式の左辺に与える例である.

# データ形式 - 1: '成功 (優良) 回数', '失敗 (優良でない) 回数' の2列
res_glm1 <- glm(cbind(n_pos, n_tot - n_pos) ~ size + hr_invest + sdg, family = binomial,
  data = perf_dat1)
summary(res_glm1)
#> 
#> Call:
#> glm(formula = cbind(n_pos, n_tot - n_pos) ~ size + hr_invest + 
#>     sdg, family = binomial, data = perf_dat1)
#> 
#> Coefficients:
#>             Estimate Std. Error z value Pr(>|z|)    
#> (Intercept) -2.15049    0.38873  -5.532 3.16e-08 ***
#> sizeH        0.07844    0.26926   0.291  0.77082    
#> hr_investH   0.82333    0.27607   2.982  0.00286 ** 
#> sdgH         0.61585    0.35132   1.753  0.07961 .  
#> ---
#> Signif. codes:  0 '***' 0.001 '**' 0.01 '*' 0.05 '.' 0.1 ' ' 1
#> 
#> (Dispersion parameter for binomial family taken to be 1)
#> 
#>     Null deviance: 15.2547  on 7  degrees of freedom
#> Residual deviance:  2.3921  on 4  degrees of freedom
#> AIC: 36.198
#> 
#> Number of Fisher Scoring iterations: 4
exp(coef(res_glm1))  # オッズ比
#> (Intercept)       sizeH  hr_investH        sdgH 
#>   0.1164275   1.0815951   2.2780664   1.8512246

回帰係数を指数変換した値 \(e^{\beta_j}\) は, オッズ比を表す. 例えば, hr_investHの係数 0.823 より, \(e^{0.823} \approx 2.28\) となり, 規模とSDGs活動が同じであれば, 人材投資が高い企業が優良企業であるオッズは, 低い企業の約2.3倍である. 同様に, SDGs活動が高い企業のオッズは, 低い企業の約1.9倍である (ただし有意水準5%では有意ではない). 一方, 規模 (sizeH) の係数は有意ではなく, オッズ比もほぼ1である.

線形回帰分析の時と同様, 二つのモデルの間に包含関係 (ネスト, “nested”) がある場合には, 関数anova()を適用することで, 追加された項が (まとめて) 有意かどうかを評価することができる. glm()の場合は, 逸脱度 (deviance) の差を用いた尤度比検定 (カイ2乗検定) を行うため, 引数test = "Chisq" (または "LRT") を指定する.

res_glm2 <- glm(cbind(n_pos, n_tot - n_pos) ~ hr_invest + sdg, family = binomial,
  data = perf_dat1)
summary(res_glm2)

anova(res_glm2, res_glm1, test = "Chisq")の結果より, 規模を加える (自由度1を使う) ことによる残差逸脱度の減少は 0.085 とごくわずかで, \(p\)値は 0.77 であり, 有意ではない. 一方, 切片のみのモデルと人材投資・SDGs活動の2変数のモデルを比べると, 2変数を加える (自由度2を使う) ことで, 残差逸脱度が 15.25 から 2.48 へと 12.78 減少し, \(p\)値は 0.0017 であり, 有意水準1%で有意である. すなわち, 人材投資とSDGs活動は, 優良企業の発生をよく説明している.

7.3 オッズ比と相対リスク

ロジット回帰の係数を指数変換した値はオッズ比であるが, 実務では「リスク (発生確率) が何倍になるか」を知りたいことが多い. 両者の関係を整理しておく.

2値の要因 \(X\) (例: 人材投資が H なら1, L なら0) と, 2値の結果 \(Y\) (優良企業なら1) について, 次の2×2の表を考える.

\(Y=1\) (優良) \(Y=0\) (優良でない) 計
\(X=1\) (H) \(A\) \(B\) \(A+B\)
\(X=0\) (L) \(C\) \(D\) \(C+D\)
  • 相対リスク (リスク比, relative risk, RR): 要因がある場合のリスク (発生確率) は, ない場合の何倍か \[ RR = \frac{P[Y=1 \mid X=1]}{P[Y=1 \mid X=0]} = \frac{A/(A+B)}{C/(C+D)} \]
  • オッズ比 (odds ratio, OR): 要因がある場合のオッズは, ない場合の何倍か \[ OR = \frac{P[Y=1 \mid X=1]/P[Y=0 \mid X=1]}{P[Y=1 \mid X=0]/P[Y=0 \mid X=0]} = \frac{A/B}{C/D} = \frac{A \times D}{B \times C} \]

発生が稀な場合 (\(A \ll B\), \(C \ll D\), すなわち \(A + B \approx B\), \(C + D \approx D\)) には, \(RR \approx OR\) となる. すなわち, 発生確率が小さいときは, オッズ比 (ロジット回帰の \(e^{\beta}\)) で相対リスクを近似できる. 一方, 発生確率が大きいときは, オッズ比は相対リスクより (1から離れる方向に) 大きく出るので, 「リスクが \(e^{\beta}\) 倍」と読むと過大評価になる.

企業パフォーマンス・データで, 人材投資の水準ごとに集計して確かめてみる.

tab <- aggregate(cbind(n_pos, n_tot) ~ hr_invest, data = perf_dat1, FUN = sum)
tab$risk <- tab$n_pos/tab$n_tot  # リスク (優良企業の割合)
tab$odds <- tab$n_pos/(tab$n_tot - tab$n_pos)
tab
#>   hr_invest n_pos n_tot      risk      odds
#> 1         L    59   350 0.1685714 0.2027491
#> 2         H    27    83 0.3253012 0.4821429
c(RR = tab$risk[2]/tab$risk[1], OR = tab$odds[2]/tab$odds[1])
#>       RR       OR 
#> 1.929753 2.378027

人材投資が高いグループの優良企業の割合は約33%と「稀」とは言えないため, オッズ比は相対リスクをかなり上回る. これに対して, 個人ローン・データ (デフォルト率は全体で約3.3%) では, 職種についてのオッズ比と相対リスクはほぼ同じ値になる.

tab2 <- table(職種 = default$職種, デフォルト = default$デフォルト)
tab2
#>     デフォルト
#> 職種    0    1
#>    A 2123   92
#>    B 5127  158
risk <- tab2[, "1"]/rowSums(tab2)
odds <- tab2[, "1"]/tab2[, "0"]
c(RR = unname(risk[2]/risk[1]), OR = unname(odds[2]/odds[1]))
#>        RR        OR 
#> 0.7197771 0.7111414

(注) この単純な集計では, 職種Bのデフォルト率は職種Aより低く (オッズ比は1未満), 上のロジット回帰の結果 (職種Bのオッズ比は約2.0倍) と向きが逆になっている. これは, 職種Aの方が平均的にローン残高が大きく, その影響が単純な集計には混ざっているためである.

aggregate(ローン残高 ~ 職種, data = default, FUN = mean)
#>   職種 ローン残高
#> 1    A   988.1525
#> 2    B   767.0036

ロジット回帰では, ローン残高と収入を同じに揃えた上での職種の効果を推定しているので, 結果の向きが異なり得る. 重回帰分析で学んだ「他の変数の影響を取り除く (統制する)」という考え方は, ロジット回帰でも同じである.

(参考) オッズ比が便利な理由の一つは, データの集め方によらず推定できる点にある. 例えば, デフォルトした人としなかった人を別々に (結果 \(Y\) で層別して) 集めたデータ (疫学でいう「ケース・コントロール研究」, 後ろ向き研究) では, \(P[Y=1 \mid X]\) (リスク) は推定できないが, オッズ比は推定できる. また, リスクの差 \(P[Y=1 \mid X=1]-P[Y=1 \mid X=0]\) は寄与リスクと呼ばれる.

疑似\(R^2\)は, 方法により相当異なることが確認される. したがって, 線形回帰の\(R^2\)のように「何%を説明している」とは解釈せず, 同じ指標で複数のモデルを比較する目的で使うのが良い.

最もよく使われる McFadden の疑似\(R^2\)は, モデルの対数尤度 \(\log L\) と, 切片のみのモデルの対数尤度 \(\log L_0\) を用いて, \[ R^2_{\text{McFadden}} = 1 - \frac{\log L}{\log L_0} \] と定義される. 直接計算して確かめておく.

1 - as.numeric(logLik(res_glm))/as.numeric(logLik(glm(デフォルト ~ 1, family = binomial,
  data = default)))
#> [1] 0.466403

パッケージpsclの利用

pscl::pR2()
- 以下を出力:
- llh: The log-likelihood from the fitted model
- llhNull: The log-likelihood from the intercept-only restricted model
- G2: Minus two times the difference in the log-likelihoods
- McFadden: McFadden's pseudo r-squared
- r2ML: Maximum likelihood pseudo r-squared (Cox-Snell に対応)
- r2CU: Cragg and Uhler's pseudo r-squared (Nagelkerke に対応)
# install.packages('pscl')
library(pscl)

パッケージperformanceの利用

performance::r2()
- モデルに応じて適切な疑似R2を選んで出力:
  - Logistic models: Tjur's R2
  - General linear models: Nagelkerke's R2
  - Multinomial Logit: McFadden's R2
  - Models with zero-inflation: R2 for zero-inflated models
  - Mixed models: Nakagawa's R2
  - Bayesian models: R2 bayes
# install.packages('performance')
library(performance)
performance::r2(res_glm)
#> # R2 for Logistic Regression
